# Publish an approved manual Fused tech short

Authority: Nick's explicit topic and publishing instruction, then SOURCE-OF-TRUTH. This manual format is separate from scheduled coin and business jobs. Do not add these topics to an automatic queue or change model, voice or schedule settings.

The installed renderer and its production SOP live at `/Users/nick/Documents/ChatGPT/Fused Tech Reels/`. Versioned copies are in `video/tech-shorts/`. Read `LOCAL-PRODUCTION-SOP.md` before producing a new export. The renderer never publishes; the publishing owner performs the steps below only after Nick authorizes publication.

1. Use the exact reviewed version from `Out/`. Never substitute the earlier MP4 after a repair. Keep the original files. The approved short profile is 720 by 1280, 30 fps, H.264/AAC, 45-85 seconds and below 25,000,000 bytes.
2. Verify the MP4 hash against the final QA and visual review. Require successful decoding, audio/video sync, loudness, true peak, hero at frame zero, correct duration and file size. Check the exact hook and CTA against actual recognition records. Review the encoded frames, not just source artwork.
3. Caption caches contain clean artwork only. Every frame receives a fresh composition. Old captions end before the next phrase begins. Preflight must reproduce multiple phrase changes after the chart-cache threshold and verify that expired text is removed. Final QA samples 16-18 seconds and late chart frames, with decoded caption-band comparison against clean composites. A single midpoint image is insufficient.
4. Copy the final MP4 to `public/reels/<slug>/<slug>.mp4`, which is gitignored. Preserve the narration and timing evidence in `content/tech-education/releases/<slug>.json`. Record the real owner generation and publication requests. Set `format: fused-tech-short-v1` in `reel-script.md` and retain every approved narration line verbatim.
5. Write the matching sourced article and assets using the normal blog template. Keep the actual tool output separate from illustrative diagrams. Disclose synthetic data and the limits of measured examples. Use root-relative internal links and the corrected hosted reel in `social-video.json`.
6. Run article lint and `qa-local.mjs`. The manual short validator requires full final-media evidence, exact speech/script/hook/CTA binding, local MP4 hash and independent ffprobe measurement. It does not change the regular reel validator or relax scheduled release gates. Record the editorial review and exact article artifact hashes in `qa.json` after reading the article and inspecting the graphics.
7. Upload only the selected final media through `sync-buffer-media-kv.mjs --platform=youtube --slugs=...`. This hosts the files; it does not create Buffer posts. Verify complete public bytes and hashes. Buffer scheduling is a separate authorized action.
8. Register the reviewed posts with `add-to-posts.mjs`, update topic history and sitemap, commit and push on main under the git policy, then use `scripts/deploy-approved-blog.mjs`. Keep the reviewed deployment baseline synchronized with committed main. Verify all new article URLs, canonical metadata, heroes and playable video URLs live.

Do not encode again for a blog copy change, a Git push or a delivery problem. Reuse the hash-valid reviewed MP4. Do not commit renders, audio, credentials, caches or runtime logs to GitHub.
