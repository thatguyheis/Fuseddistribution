# Daily Business Growth Blog and Reel SOP

This procedure applies only to the Codex automation `daily-business-growth-blog-and-reel`, which Nick authorized for two business-growth blog/reel pairs per Pacific day from the v2 365-day plan. It is a narrow exception to the repository's coin-only production scope. Keep `ops/content-scope.json`, coin-history scope, and all other publishing scope unchanged. The run starts at 23:00 Pacific, after the 22:00 Buffer refill, and completes the two topics serially so local TTS and video rendering stay in the overnight window. Attribute both topics to the Pacific date when the batch starts, even if the run crosses midnight.

The scheduled task uses GPT-6 Luna with low reasoning for monitoring and routine production. Codex owns the review and downstream work; routine review is not handed back to Nick. Keep the daily run checkpoint in `.workflow-state/business-growth-ai-365/` and resume the same topic after a blocker rather than selecting a duplicate. Record both nightly topics as separate entries in `inProgressTopics[]` in the ledger and a per-topic stage map in the dated run report; never overwrite one topic's IDs or evidence with the other's. A completed topic may wait for Buffer reconciliation without preventing the second topic from advancing.

3. Apply an attention-first story review to each reel before editorial approval. The first frame and spoken hook must show a specific viewer problem or benefit immediately, with no greeting, logo lead-in, or vague promise. Deliver the hook's answer early, then use two to four short payoff beats; every chart, graph, or flowchart must make a source-backed point or clarify a step. Include one relevant CTA with one primary action only. Prefer a short question for comments or a clear save/share prompt when that matches the content. Never stack “like, comment, follow, and share.” Record the hook promise, hook duration and word count, payoff beat map, one CTA/action, hypothesis, and metrics to inspect in `attention-review.json`.
4. Finish content and deterministic checks before editorial sign-off. Run local blog QA and repair its findings first. Review the article, research, reel script, narration data, attention review, social copy, and actual exported graphics. Prefer clear charts, graphs, checklists, and flow diagrams that explain verified facts or a repeatable process. Use relevant cleared stock or owner imagery when it adds context. Stable Diffusion is optional and disabled by default; enable it only for a specific reviewed visual gap, never as the default source of charts or evidence. Follow `docs/EDITORIAL-HERO-SOP.md` and `docs/REEL-OPENING-SOP.md`: inspect the actual export full size and at phone size (about 360 px wide). Conceptual illustrations must be identified as conceptual; invented values must never appear as real measurements.
5. Record the completed owner review in `artwork-qa.json` and `qa.json`. Add `attentionOptimizationVersion: 1` and hash `attention-review.json` in `qa.json`. The renderer gate validates that the review maps to the actual hook and ending card, the spoken hook is at most 12 words and 4 seconds, the CTA is at most 10 words with exactly one primary action, and the review names a retention or action metric. `qa.json` must have `pass: true`, no blockers, score at least 85, `mode: "codex-editorial"`, and SHA-256 hashes for the exact current approval artifacts required by `video/scripts/approved-sources.mjs`. Verify with `node video/scripts/approved-sources.mjs <slug>`. **Order matters:** `qa-local.mjs` writes `mode: "deterministic-local"`; running it after editorial sign-off erases the renderer's approval record. If deterministic QA must run again, repeat the owner review and refresh every hash before rendering or deployment. Deployment's QA call writes to `/tmp` and preserves the source approval record.
6. Render only after the approved-source gate passes. Produce the two selected reels serially and only during the 23:00–06:00 Pacific overnight window, after the Buffer refill has released the publisher lock. Never overlap renders or compete with an active render lock. Use the repository's pinned voice, music, caption, media-rights, duration, size, and release checks. Keep `GENERATIVE_MEDIA_ENABLED=0` unless a documented visual gap requires an approved one-off. Wait on the existing command/session when available. If monitoring by process and files is necessary, check no more often than once per minute and report only a meaningful stage change. Respect `/tmp/fused-remotion-render.lock`: never start a duplicate render or remove its lock while the recorded process is alive or ownership is unknown. 7. A Buffer outage blocks social scheduling and live reconciliation only. It does not block research, writing, local QA, editorial review, or media preparation. Complete each blog/reel pair and embed the playable reel only after the final hosted MP4 is verified. Deploy through `scripts/deploy-approved-blog.mjs` against the reviewed baseline, then verify the canonical page returns HTTP 200. Treat only an explicit `sent` response with matching channel, sent time, external link, and video asset as delivered. Keep unknown or missing IDs unresolved; do not republish or advance the checkpoint. If the authorized network path still fails, stop Buffer work and record the exact error. If live status fails for an API/provider reason, counts are unknown, or `.buffer-live-unavailable.json` records an active cooldown, do not try other Buffer endpoints or use cached counts to authorize new posts. For HTTP 429, preserve and obey its exact retry time, finish independent work, and retry the same package after cooldown. Never create a duplicate post.

## Hook, CTA, and performance learning

- Treat platform recommendations as testable creative guidance, not universal guarantees. TikTok's business guidance emphasizes the proposition in the first three seconds, a hook/body/close structure, and one clear CTA; Meta describes Instagram average watch time as a way to assess whether the hook holds attention; YouTube recommends inspecting retention dips, spikes, and top moments and comparing against similar-length videos.
- For every new reel, record one hook hypothesis and one primary success metric. Use the opening seconds to state a concrete outcome or problem and show a relevant visual. Avoid a false curiosity gap: pay off the promise early. Keep the original question or story alive with useful steps, meaningful visual changes, and source-backed graphics rather than repeated title cards.
- The final spoken/on-screen CTA should ask for one action. Use a specific, low-effort comment prompt when discussion is the goal, a save prompt for a reference/checklist, a share prompt when another person benefits, or a link prompt only when there is a relevant destination. Keep secondary actions out of the same CTA.
- Reconcile each platform's native analytics after enough data is available: Instagram average watch time, total watch time and sends; TikTok average watch time/completion and CTA response where available; YouTube Shorts viewed-versus-swiped-away, average view duration and audience-retention moments. Compare like with like (platform and similar duration), use the account's rolling baseline and include sample size. YouTube notes retention data may take 1–2 days and detailed highlights require sufficient views; never label an early or tiny sample as a winning hook.
- Change one creative variable at a time when possible. Record measured results in the existing feedback/performance workflow and carry forward only improvements supported by evidence. Do not optimize for views alone or insert invented performance benchmarks into the SOP.

## Overnight work and CPU limits

- The scheduled automation starts at 23:00 Pacific, after Buffer's 22:00 refill, and creates two nonduplicate blog/reel packages. It renders them serially; the Mac must be awake and available overnight for local TTS and Remotion.
- The coin-history renderer runs at 01:00 and 04:00 Pacific with a cap of two reels per invocation and a shared lock. It must not start another render if the prior run owns the lock. Production does not alter the coin scope or the separate daily target.
- Stable Diffusion stays opt-in (`GENERATIVE_MEDIA_ENABLED=0` by default). Data graphics and flow diagrams are deterministic, lighter and preferred when they explain the point. Do not allow an optional image-generation timeout to consume the overnight render window.
- If an overnight batch does not finish, preserve the checkpoints and exact incomplete stages, report one actionable failure, and resume in the next overnight window; do not push heavy rendering into daytime or start parallel renders.

## Recovery notes

- Check deployment baseline paths directly before reporting them missing: `.workflow-state/deployment-baseline/wrangler.jsonc` and `.workflow-state/deployment-baseline/public/blog/posts.json`. Use the exact error from `scripts/deploy-approved-blog.mjs`; do not infer absence from a directory listing or another failed prerequisite.
- The status command above checks cooldown before making a Buffer request. A sandbox-blocked `fetch failed` is not a provider response and does not establish a Buffer cooldown; use the narrowly authorized network-enabled execution path once. Only an actual Buffer HTTP 429 establishes a cooldown and retry time. Do not repeatedly probe after a provider failure.
- Recent sent-history pagination is bounded and may be incomplete. When known scheduled IDs are missing from the live queue, retrieve each exact ID with `status --post-ids=...`; do not use incomplete history as evidence that posts failed or were never sent.
- Local content QA, editorial hash approval, deployment, media hosting, and Buffer status are separate gates. A failure in the last gate must not cause already completed content to be rebuilt. A failure in an earlier gate must not be represented as a successful publication.
- Keep SOP and automation prompt aligned. When a verified defect changes the order or safe command, update this procedure and the automation prompt in the same repair, then record the observed defect and verified fix in that day's run report.
