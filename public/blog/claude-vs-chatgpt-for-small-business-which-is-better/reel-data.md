## segments
- type: overlay
 text: DEFINE THE BUSINESS TASK
 narration: Choose a repeated task with an output someone can check, such as drafting a reply from an approved FAQ. Write the required result before comparing products. A response must preserve the supplied policy and avoid invented commitments. A polished answer is not enough if it answers the wrong question or changes the business facts. Check the complete response.
- type: overlay
 text: RECORD THE CONFIGURATION
 narration: Record the product, plan, date, visible model selection and enabled tools for each run. Give both candidates the same source packet and expected outcome. If one has extra sources or a different tool, make that difference explicit. Product names alone do not explain what was actually available during the comparison.
- type: overlay
 text: CHECK SOURCE ACCURACY
 narration: Include a question the supplied material cannot answer. The expected response should identify the gap rather than invent a promise. If an answer cites a source, check that the source supports the actual claim. Keep failed examples as well as successes, and distinguish factual corrections from preferences about writing style.
- type: overlay
 text: VERIFY THE WORKSPACE FIT
 narration: Both products document ways to organize project context, but the actual account and permissions still matter. Check who owns the workspace, what material can be supplied and which actions are enabled. A feature in documentation does not prove it is available or configured for the employee who will use it.
- type: overlay
 text: MEASURE COMPLETE EFFORT
 narration: Consider a hypothetical timing example, not a Claude or ChatGPT benchmark. One candidate takes two minutes to generate and eight to review, totaling ten. Another takes four minutes to generate and three to review, totaling seven. Comparing generation time alone would give the opposite ordering. Keep the full task and sample size visible.
- type: overlay
 text: CHOOSE WITHIN THE EVIDENCE
 narration: Check current account costs, seats and allowances rather than assuming fixed prices or equal limits. Make the final decision for the tested job and recorded configuration. Save the review checklist and revisit it when the setup changes. If neither result meets the requirements, improve the task or source before expanding the subscription.
