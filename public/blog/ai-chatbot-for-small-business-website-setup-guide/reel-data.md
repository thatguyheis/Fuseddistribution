## segments
- type: overlay
 text: DEFINE THE WEBSITE JOB
 narration: Start with a narrow job for your website chatbot, such as explaining hours, service area and the estimate request process. Write the expected answers before setup. An assistant can explain how to request an appointment without claiming that an appointment has actually been confirmed. Keep those two outcomes separate in your tests.
- type: overlay
 text: CHECK THE AI ALLOWANCE
 narration: Check the allowance inside your account before relying on ongoing service. In the documented Tidio example, the initial Lyro allowance is fifty AI conversations and does not renew. That is different from a paid monthly allowance. Keep a normal contact page available if automated answers stop, and assign someone to check usage.
- type: overlay
 text: INSTALL AND VERIFY DELIVERY
 narration: Use the installation method documented for your website platform and the code from your own project. Check for an existing installation before adding another copy. Then open the published site on desktop and mobile. Send a labelled test message and find it in the receiving inbox. A visible button alone does not prove delivery.
- type: overlay
 text: TEST WHAT THE BOT KNOWS
 narration: Use a small approved answer set and fictional customer questions. Ask about known hours, an unlisted holiday and an unsupported service. Compare each response with its expected outcome. If an answer invents a policy, preserve the failed case, correct the source or configuration, and repeat the test before making public responses available.
- type: overlay
 text: VERIFY THE STAFF HANDOFF
 narration: Ask for a person while staff are available, then repeat while they are unavailable. Confirm where the message arrives and who will handle it. The visitor message should match your real staffing arrangement. A sentence saying the conversation was transferred does not prove that someone has accepted responsibility for the next response.
- type: overlay
 text: KEEP A REPAIR RECORD
 narration: Record the launch settings, responsible staff member and a way to disable automated responses. When a problem appears, distinguish a wrong source answer from missing message delivery or an exhausted allowance. Repair the identified cause and repeat the relevant test. Measure resolved requests and corrections rather than promising an automatic increase in sales.
