# Map old URLs before a redesign

## hook
A redesigned website can leave useful old links pointing nowhere. Make a page by page map before launch: each old address, its intended new destination, the decision behind it, and a separate test result. Keep planning and testing in separate columns, because an approved destination does not prove a redirect works.

## segments
- type: overlay
 text: FIND EVERY ADDRESS
 narration: Begin with more than the navigation menu. Review your content system, sitemap, analytics, server logs and important links in profiles or customer emails. Each source has limits, so combine them and preserve the original inventory. Note when an address belongs to a booking provider your business does not control.
- type: overlay
 text: CHOOSE A RELEVANT PAGE
 narration: For each old address, record whether it stays, moves, merges or is removed. Match a moved page to the new page that serves the same visitor need. Do not send unrelated pages to the homepage just to avoid a missing page. If content has no relevant replacement, ask your developer how it should be retired.
- type: overlay
 text: RECORD THE DECISION
 narration: Use columns for the old URL, page purpose, planned destination, decision, owner and notes. Mark uncertain rows for follow up. A business decision about where content belongs is different from evidence that the redirect is installed. Date the map and retain the original address list for later checks.
- type: overlay
 text: TEST THE FINAL PATH
 narration: On a safe preview or after the approved change is deployed, request the old address and follow the full path. Check the response, final destination and page content. Record what happened. Ask the developer about external booking links or routes the business does not control. Keep private access tokens and customer identifiers out of a shared map.
- type: overlay
 text: CHECK THE NEW SITE
 narration: Update internal links and the sitemap to the new addresses. Google recommends direct permanent server redirects when possible, avoiding long chains and irrelevant destinations. Test canonical details and important customer actions on the live pages too. Check both the HTTP result and destination relevance. Verify important customer actions on the new page.
- type: overlay
 text: KEEP A CLEAR RECORD
 narration: Save unresolved exceptions, the person responsible and the retest result with the map. Google advises keeping move redirects for as long as possible, generally at least one year. Search visibility may fluctuate while pages are recrawled, so promise no ranking outcome.
