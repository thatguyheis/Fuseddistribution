# Reel Script: how-to-request-indexing-after-updating-a-service-page
format: long-form
segments: 6
target-duration: 120s

---

## HOOK

**Visual:** Page updated. What comes next?
**Duration:** 18s minimum

Narration: After updating a service page, confirm the public page contains the finished changes, then use Google Search Console's URL Inspection tool to request indexing for that exact address. Keep the request separate from evidence that Google has indexed the revision. A saved edit in your website dashboard does not establish that the public page has changed.

---

## OVERLAY: VERIFY PUBLIC COPY

**Visual:** Verify public copy
**Duration:** 16s minimum

Narration: Open the public address in a separate browser session. Read the headline, service description, contact details, and main call to action. Compare them with your approved change list. If the old copy is still visible, resolve the publication or caching issue before treating the update as ready for search review.

---

## OVERLAY: RECORD INSPECTION RESULT

**Visual:** Record inspection result
**Duration:** 21s minimum

Narration: Capture the result shown by the tool, the date, and the inspected URL. A screenshot can support the note, but write the result in text too so the next person does not have to infer it from an image. If the tool reports an issue, preserve its wording and pass it to the person responsible for the website rather than repeatedly clicking the request control.

---

## OVERLAY: SEPARATE REQUEST AND RESULT

**Visual:** Separate request and result
**Duration:** 30s minimum

Narration: That distinction matters when someone asks whether the update is done. You can report that the page is published and tested while search processing remains unconfirmed. Avoid saying the new copy is ranking merely because a request was accepted. Choose a later review date and a named owner. At that review, record the current Search Console evidence and any remaining issue. Preserve the earlier request date so the team can see what changed. Do not overwrite the log with a single green status that hides whether the result refers to publication, a request, or observed indexing.

---

## OVERLAY: KEEP A CHANGE LOG

**Visual:** Keep a change log
**Duration:** 17s minimum

Narration: A useful record contains the URL, summary of the content change, publication check time, request time, tool result, owner, and next review date. Add the reason for the update, such as corrected hours or a clearer service description. Keep customer details and private account screenshots out of a shared public document.
