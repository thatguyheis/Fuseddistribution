# Reel Script: schedule-ai-tasks-to-follow-your-sop
format: long-form

---

## HOOK
**Duration:** 4s minimum
Narration: Can AI keep your SOP moving?

---

## OVERLAY: Schedule a known process
Narration: A schedule can start recurring work, but it does not make the work reliable by itself. First define the input, steps, expected output, source access, permissions, and what the task must do when something is missing. The SOP owns that process.

---

## OVERLAY: Example one: daily lead drafts
Narration: Each morning, an AI task can read an approved lead view, summarize new inquiries, and save draft replies for a staff member. The SOP can forbid sending messages or guessing missing details. A person checks consent, names, and the draft before contacting anyone.

---

## OVERLAY: Example two: weekly status report
Narration: On Friday, a task can summarize unfinished work from an approved project tracker. Include owners, due dates, and blockers. If the tracker is unavailable, record a failed run. Never pass last week’s information off as current.

---

## OVERLAY: Connect the real source
Narration: Make sure the scheduled system can read the current SOP and allowed data. A project file is not automatically available to every scheduled task. Use a supported connection or a local workflow with the exact folder access, and confirm it before the first run.

---

## OVERLAY: Set permissions and stop rules
Narration: Say what the AI may read, create, and change. For customer messages, start with drafts only. Stop on missing consent, conflicting instructions, denied access, or incomplete data. Save the blocker and the next safe step for a person.

---

## OVERLAY: Check each actual run
Narration: A schedule being active does not prove a task finished. Review the run record and destination. Confirm it used the right source and SOP. Check the expected output and make sure there is no duplicate. Verify the exact post or record before reporting success.

---

## OVERLAY: Begin with one safe task
Narration: Pick a recurring job with an easy to inspect result. Schedule one draft only run, compare it with the SOP, and fix the steps that failed. Add more access or actions only after the first workflow is dependable.
