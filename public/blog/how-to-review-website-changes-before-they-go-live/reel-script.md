# Reel Script: how-to-review-website-changes-before-they-go-live
format: long-form
segments: 7
target-duration: 120s

---

## HOOK

**Visual:** Website review checklist diagram
**Duration:** 13s minimum

Narration: A website preview can look finished while the customer journey still fails. Before approving changes, decide what should work, test that action and write down the result. Start with the change request, not just the homepage.

---

## OVERLAY: DEFINE THE CHANGE

**Visual:** Website review checklist diagram
**Duration:** 16s minimum

Narration: Name the pages involved and the result you expect. For a booking button, check that it opens the right service in the right calendar. Record the preview address and version. If the preview changes during your review, agree which checks need to be repeated before you approve it.

---

## OVERLAY: CHECK THE DETAILS

**Visual:** Website review checklist diagram
**Duration:** 16s minimum

Narration: Read the changed copy against your current business information. Confirm prices, opening hours, service descriptions and contact details. Look at the surrounding text too, including the footer. Check that images represent the work accurately and that you have permission to use them. Put placeholders on the correction list.

---

## OVERLAY: FOLLOW THE JOURNEY

**Visual:** Website review checklist diagram
**Duration:** 17s minimum

Narration: Start from the page a customer would use and follow every changed link. Arrange a clearly marked form test with the receiving person. Check both the visitor confirmation and the actual inbox. For payments or bookings, agree a safe test method first so the review does not create unintended transactions.

---

## OVERLAY: MAKE FIXES CLEAR

**Visual:** Website review checklist diagram
**Duration:** 17s minimum

Narration: Check the changed pages on a phone and desktop. Try the keyboard, inspect focus and labels, and enlarge the text. These are initial accessibility checks, not a complete evaluation. For each problem, record the page, your steps, what happened and what you expected. Identify which issues must be fixed before publication.

---

## OVERLAY: VERIFY THE RELEASE

**Visual:** Website review checklist diagram
**Duration:** 17s minimum

Narration: Repeat each failed check after it is corrected. Approve a named version and record any accepted follow-up work. Agree who publishes and who can restore the previous version if needed. Then open the public page and repeat the important actions. Preview approval alone does not prove that the live website works.

---
