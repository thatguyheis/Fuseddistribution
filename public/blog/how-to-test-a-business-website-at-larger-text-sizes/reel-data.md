# Test a Business Website at Larger Text Sizes

hook: Test a Business Website at Larger Text Sizes

## segments
- type: overlay
 text: COMPARE ENLARGED VIEW
 narration: Take a baseline look at the chosen page before changing the setting. Then enlarge it and read the same content in the same order. Note words hidden behind another element, controls that disappear, or instructions that no longer fit beside their field. Keep the URL and setting with each observation. A cropped screenshot without that context can make an otherwise useful report difficult to reproduce.
- type: overlay
 text: FOLLOW THE ACTION
 narration: Open the menu, choose the service, and continue to the contact or booking destination using the enlarged view. A readable headline is not enough if the next control becomes unreachable. Check content inside cards, banners, dialogs, and preview frames separately. Record which container clips the content rather than describing the whole website as too large. The location of the failure often determines who needs to fix it.
- type: overlay
 text: CHECK FIXED CONTROLS
 narration: Look closely at labels, field instructions, and any control that stays fixed on screen. Check whether a banner obscures the current field or prevents reaching the next action. Use sample input without submitting a false customer enquiry. If an error state needs testing, agree on a safe method with the site owner and preserve the exact sequence that produced the problem for the developer.
- type: overlay
 text: REQUEST A REPAIR
 narration: Send the developer the page address, enlargement setting, browser, and expected task. Explain what becomes unavailable and where you observed it. Ask them to retain readable content and usable controls rather than shrinking the text back to the original appearance. When the repair affects a shared component, list another page that uses it so the change can be checked beyond the first example.
